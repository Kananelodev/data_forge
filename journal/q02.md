# q02 · Warehouse



## In plain words


- Bronze is never edited because we wanna keep the source data as the original so that in the future should our cleaning logic have a bug we have the original data to go back to

- The reason every bronze is a text is because we don't wanna throw away any "data", we want to ingest whatever data without changing it which goes back to why we never want to edit bronze, so which means whatever data we get is the data we stick should it be in bad data format

- Lineage columns allow us to be able to have proof of when we ingested the data and these columns gives us audit power in a way

- I hit the "schema already exits" because the I did not add the IF NOT EXISTS which checks if the schema already exist or not

## The proper terms

- Bronze has immutability: this means you can't edit the data and this is by design so you have original source data

- Because Bronze data has immutability this means that you have to ingest all kinds of data and the simplest way to do that is by making every data entry a text

- Data lineage columns allows us to have audit proof should someone try to verify the validity we can go to the lineage columns, usually the _ingested_at and source-file are standard lineage columns

- I hit the "schema already exits" because the I did not add the IF NOT EXISTS which checks if the schema already exist or not

- Idempotent: Running something again gives the same result
Immutable: What is stored never changes after it is written

- Schema drift: It is when the source changes shape over time and it's the cause of most real pipelines
